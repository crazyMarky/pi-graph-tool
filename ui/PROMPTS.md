# 测试提示词集（v2：自主规划优先）

## 先说清楚一件事：静态规划与动态规划

**graph_run 的单次调用 = 一张静态 DAG**：调用那一刻全图定型，执行中节点不会增生（屏障语义要求确定性——这是 v0.2 的设计选择，换来的是可复现调度与失败级联的可推演性）。

**动态性存在于两个层面**，都可以测：

1. **拆解决策动态**：提示词只给目标，**不给结构**——怎么拆、拆几波、谁依赖谁，全由主 agent 当场判断。同一个目标不同模型拆出的图不一样，这正是"编排智能"的观测点
2. **多轮再规划动态**：主 agent 看到第一轮结果后**再次调用 graph_run**（或改用直接回答），形成"规划→执行→观察→再规划"循环。执行中发现预设与现实不符，靠这个循环消化

执行中途节点增生（TDAG / Flow 式动态任务图，见 arXiv:2608.21156 第 4.5 节）属于图工程的开放方向，当前版本未实现——如实告知。

## A 组 · 自主规划型（实用任务，不写任何结构暗示）

> 特征：只描述目标和约束。模型自己决定图的形状。

**A1 竞品分析（真实工作场景）**

```
对比 Supabase、Firebase、PocketBase 三个后端即服务产品，我们要给一个独立开发的移动 App 选型，关心：免费额度、离线能力、数据迁移风险、社区活跃度。给出评分表和明确建议。
```

**A2 代码库体检（工具节点会自然出现）**

```
分析这个项目的代码结构：哪些模块职责清晰、哪些存在耦合风险、依赖里有没有过时或停维护的，最后给一份可以照着做的重构优先级清单。
```

**A3 领域摸底 + 结论（多轮再规划型）**

```
我想判断 2026 年该不该把团队的技术栈迁到 Bun。先做现状调研，看完调研结果后你自己决定还需要深入查证哪些疑点，直到有把握给出"迁/不迁/部分迁"的结论为止。可以分多步进行。
```

**A4 内容生产（天然多分支）**

```
为我们的开源项目（一个 Markdown 笔记应用）准备发布材料：GitHub README 重写、三条社交媒体宣传文案、一份常见问题 FAQ 初稿。风格参考项目现有文档。
```

**A5 学习路径（深流水线自然涌现）**

```
给一个会 HTML/CSS/JavaScript 但没用过框架的人，设计一条六周上手 React 的学习路径：每周目标、练习项目、自测标准，最后说明这条路径的取舍理由。
```

**A6 决策支持（菱形依赖）**

```
我们在三个人才招聘渠道（猎头、内推、招聘网站）之间分配明年的预算。各渠道的成本结构、质量、风险自己调研评估，输出一份带权重的预算分配建议。
```

**观测点**：A 组不规定结构，不同模型/代际拆出的节点数、波数、依赖形状都会不同。GLM-4.5 对 A1 类任务通常自发产出"并行调研 + 汇总"两波；能力更强的模型会更敢于建深依赖。**这本身就是实验数据**——把它和"阶段写死"的 B 组对照，就是"编排智能在模型侧"的直接证据。

## B 组 · 受控观测型（只为压测调度语义，日常别用）

> 特征：显式写阶段。用途只有一个——稳定生成深图来检验拓扑分层、数据路由、屏障、失败语义的实现正确性。上一版全是这一组，本组保留并压缩。

- **B1 深流水线**（实测 8 节点 / 4 Wave）："分四阶段做 PostgreSQL/MongoDB/Redis 选型：①并行调研原理与场景 ②分别评估用于电商订单系统 ③交叉核对假设矛盾 ④汇总建议。阶段间严格依赖，同阶段内互不依赖。"
- **B2 工具节点**："分析本项目目录文档：第一阶段并行读取归纳各类文件主题（读文件可用 read 工具），第二阶段交叉对比，第三阶段输出主题地图。"
- **B3 失败语义**："第一阶段三个节点各自只输出数字 7、3、9，不要其他文字；第二阶段求和只输出结果。"——观测违约挽回/级联跳过（GLM 可能将超短回答放入思考通道而失败，属厂商行为差异活教材）

## 使用建议

- 演示/日常：用 **A 组**——真实、且顺带观测模型编排智能
- 回归测试/给评委展示调度机制：用 **B1**（稳定 4 Wave）+ **B3**（失败路径）
- 研究对比：同一 A 组任务跑不同模型，对比 plan 的节点/波数/依赖形状

## 已知模型怪癖备注

- **GLM-4.5 偶发重复调用 graph_run**：任务完成答案已返回后，模型可能紧接着再发起一次相同参数的 graph_run（第二次通常无进展、被空置）。UI 上表现为一块只长出"用户节点+规划"就停住的图——以第一块完整图和主回答为准，已实测（v0.3.2 排查记录：首个 run 3/3 成功 124s，第二个 run 0 事件）
- **GLM 超短回答进思考通道**：P6 类任务可能因 reasoning_content 吞掉正文而失败级联——这属于厂商行为差异，不是调度缺陷
